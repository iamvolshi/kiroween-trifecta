# KATIE Audit UI

**What did the agent do, and what did it believe when it did it?**

VOLSHi gives AI agents a tamper-evident, append-only record of what they believed, when, and why — so every action is auditable. This app is the window into that record. It reads entries from a KATIE record and shows them: what the agent believed, when it believed it, and how each belief changed over time. It reads and shows only. It never writes to the record, and nothing on screen is faked — if there is no data, it says so.

Built for [Kiroween 2026](https://kiroween.devpost.com/) with Kiro.

## What it does

- **Action List** (`/actions`) — every record entry, newest first, with its KID, subject, state, and authority.
- **Time Travel** (`/time-travel`) — pick a moment and see the record as it stood then: which entries were live, which had been revised, which had been rejected. The past stands as it was known at the time.
- **Entry Detail** (`/entry/:kid/:subject/:id`) — one entry in full: its state, authority, live interval, evidence, and reason, plus where it sits in its chain.

A KID is a number, not a name. KATIE mints it when a thing is born registered, and the same KID follows the thing through every change. Entries chain per (KID, subject); exactly one live interval at a time.

## Status — honest

The UI runs against **mock data** behind a seam adapter: four fixture entries (a temperature chain for KID 1, a pressure entry for KID 3; KID 2 is deliberately absent from the KIDMAP, so the UI must show a real "unknown KID" state, not guess). The live adapter exists as a stub and returns a typed error — it is not wired to a record yet. Wiring it to a real record is the next step, not a done thing. Nothing here pretends to be live.

## Run it

```sh
cd audit-ui
npm install
npm run dev     # local dev server
npm test        # 79 tests, 11 files, all passing (verified 2026-11-15)
npm run build   # tsc + vite build
```

Node 18+ and npm. No other services needed — the mock adapter is self-contained.

## How it's built

- **Vanilla TypeScript + Vite.** No framework. Static hosting with an SPA fallback (pathname routing: `pushState` + `popstate`, real routes, not hash routes).
- **Seam adapter.** All record reads go through one adapter interface (`src/adapter/seam.ts`). The mock adapter implements it today; the live adapter will implement the same interface against a real record. The views never know which one is behind the seam.
- **Property-based tests.** Vitest + fast-check. The property tests caught real bugs during the build, including a rendering bug where error strings were HTML-escaped through `innerHTML` (fixed by switching to `textContent`).
- **No god files.** No file over 500 lines; one concept per file. Enforced by a Kiro hook (see below).
- **Display only, no fake data.** Empty states and error states are explicit. A missing KID shows as missing. An unreachable record shows as unreachable.

## How Kiro was used

- **Spec flow.** Requirements, design, and tasks live under `.kiro/specs/audit-ui/` — 13 tasks, 29 subtasks, executed in order with review gates between phases.
- **Hooks.** `.kiro/hooks/` carries two hooks: test + typecheck on every TypeScript save, and a no-god-files check that fails any source file over 500 lines.
- **Steering.** `.kiro/steering/` carries the house rules — product (what the UI is, the KID doctrine, display-only), tech (stack, mock-first, no-holes), structure (layout, no god files). The steering files were drafted from the founder's rules, not generated by Kiro; they are what Kiro reads every session.
- **Powers.** Queued: Kane (real-browser verification) and Netlify (working app URL).

The full Kiro write-up is in the Devpost submission.
